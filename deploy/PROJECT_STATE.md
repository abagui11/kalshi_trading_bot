# Kalshi 15m bot — project state

Updated: 2026-09-08

## What this is

Local Windows bot that papers Kalshi **KXBTC15M** / **KXETH15M** 15-minute up/down markets.

- Shared ICT/HTF Claude bias (gated refresh) + strategy plugins; default **adverse-only**.
- Trades only when strategy + edge gates pass.
- Paper fill at mid; settle from Kalshi `result` (YES→$1 / NO→$0 per contract).
- Telegram: trade + why only; `/stats` and `/positions`.
- Dashboard: equity + open/closed paper trades on `DASHBOARD_PORT` (default 8081).

**Adverse-sensitive deploys:** see [`ADVERSE_CHANGELOG.md`](ADVERSE_CHANGELOG.md).

## Safety

- Live risk caps: sizing bankroll = `min(live balance, KALSHI_BANKROLL_USD)`,
  `KALSHI_DEPLOY_PCT` per trade, `KALSHI_MAX_DEPLOY_PCT` hard cap,
  `KALSHI_MAX_NOTIONAL_USD` absolute ceiling (0 = off). Exits (`closing=True`
  orders) bypass entry caps — they are risk-reducing.
- Daily loss stop (live books only): once a live bot's realized P&L for the
  UTC day reaches -`KALSHI_DAILY_STOP_PCT` (**0.35** since 2026-09-28) x the
  day-start sizing bankroll, `kalshi_regime.entry_gate` blocks its entries
  until 00:00Z. Open positions still settle. `0` disables.
  **This knob is denominated in bankroll while risk is denominated in
  contracts, so it must be revisited on every size step** — the 8→16 ct
  step left it at $56.25 (0.95 sd of a daily move, down from 1.89 sd) and it
  fired on the first day at the new size. At 32 ct even 0.35 would be
  ~0.66 sd.
- Secrets live in `secrets/` and `.env` (gitignored).
- Do not reuse the spot bot Telegram token or `ledger.db`.
- Production (VPS 45.33.97.27, `/opt/kalshi-15m-bot`, systemd `kalshi-bot`):
  `ENABLED_BOTS=eva_wick,eva_streak,eva_arb`, `KALSHI_LIVE_BOTS=eva_wick`
  (since 2026-09-22: wick = live book, favourite 67-80c mid-window,
  8 ct; streak + arb = paper),
  zero-Claude, `kalshi-lastmin` logger colocated.
- Altcoin shadow books (`eva_wick_xrp`, `eva_wick_sol`, `eva_wick_hype`) are
  in `bot_config.PAPER_ONLY_BOTS`: `bot_is_live` returns False for them
  before `KALSHI_LIVE_BOTS` is consulted, so they cannot be promoted to live
  by editing the env. Promoting one is a deliberate code change.
  **Testing epoch begins 2026-09-30T16:47:19Z** (12:47 ET) — the restart
  after the ladder fill model was withdrawn. The three entries from the first
  switch-on (16:35Z) were priced by that model and are archived in
  `paper_positions_altbadfill_20260930`, not scored. Pinned in
  `trading_bot_MVP/kalshi_bridge.py` as `_ALT_EPOCH_DEFAULT` (override
  `KALSHI_ALT_EPOCH`) rather than derived from the first trade, so the
  windows these books chose *not* to trade stay inside the record.
